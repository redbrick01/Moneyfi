# 투자 회고 허브 설계

작성일: 2026-05-31

## 요약

MONEYFY에 `투자 회고 허브`를 추가한다. 이 기능은 사용자가 매일 앱을 열 이유를 만들고, 일간/주간/월간 단위로 자신의 투자 판단을 복기하도록 돕는다. 단순 잔고 확인이 아니라 거래 판단, 성과, 현금흐름, 시장/뉴스 맥락, 다음 점검 과제를 함께 보여주는 것이 목표다.

추천 구조는 하이브리드다.

- 홈 대시보드: 짧은 `오늘의 투자 회고` 카드로 매일 확인할 이유를 제공한다.
- 분석 탭: `오늘`, `주간`, `월간` 리포트를 같은 비중으로 다루는 깊은 회고 허브를 제공한다.
- AI 코치: 사용자가 선택했을 때만 해석 문장을 보강한다. 기본 리포트는 로컬 계산만으로 동작해야 한다.

## 목표

- 사용자가 MONEYFY를 반복해서 열 만한 일간 체크인 경험을 만든다.
- 사용자가 잔고뿐 아니라 자신의 투자 판단을 되돌아보게 한다.
- 오늘/주간/월간 리포트를 모두 비슷한 완성도로 제공한다.
- 핵심 리포트는 결정적이고, 로컬 우선이며, 신뢰할 수 있게 만든다.
- AI 문장 생성은 필수가 아니라 선택형 보강 기능으로 둔다.

## 비목표

- 매수/매도 추천이나 자동 투자 조언을 제공하지 않는다.
- 기본 리포트 경험에 AI, 로그인, 네트워크 연결을 요구하지 않는다.
- 첫 버전에서 별도의 수동 투자 일지 입력 흐름을 만들지 않는다.
- 이 기능을 이유로 홈, 분석 탭, 투자성과 페이지 전체를 대규모 재설계하지 않는다.
- 원장 전체나 계정 식별 정보를 AI 서비스로 보내지 않는다.

## 제품 구조

### 홈 대시보드 진입 카드

홈 대시보드에는 하나의 compact 회고 카드를 둔다. 이 카드는 전체 리포트를 담는 화면이 아니라, 사용자를 회고 허브로 자연스럽게 보내는 진입점이다.

카드 내용:

- 포트폴리오 변화나 최근 활동을 바탕으로 한 짧은 일간 헤드라인
- 성과 변화, 의미 있는 보유/현금 변화, 뉴스/시장 맥락 중 최대 3개의 확인 포인트
- 전체 투자 회고 허브를 여는 명확한 액션
- 데이터가 부족할 때 무엇이 쌓이면 유용해지는지 알려주는 빈 상태

### 분석 탭 회고 허브

분석 탭에는 전체 `투자 회고 허브`를 둔다. 허브는 세그먼트 구조를 사용한다.

- `오늘`
- `주간`
- `월간`

세 리포트는 같은 데이터 모델과 컴포넌트 계열을 공유한다. 유지보수성을 위해 구조는 같게 두고, 각 기간별로 강조하는 내용만 다르게 한다.

### 오늘 리포트

목적: 빠른 체크인.

내용:

- 오늘의 포트폴리오 및 손익 변화
- 눈에 띄는 보유, 현금, 자산군 변화
- 사용 가능한 경우 시장/뉴스 맥락
- 오늘 확인할 포인트 최대 3개
- 사용자가 AI 코치를 켠 경우 선택형 AI 코멘트

### 주간 리뷰

목적: 투자 판단 복기.

내용:

- 주간 성과와 현금흐름 요약
- 매수, 매도, 배당, 이자, 입금, 출금, 이체, 환전 활동 요약
- 예측 적중 여부보다 포트폴리오에 어떤 영향을 줬는지에 집중한 거래 판단 피드백
- 비중 변화, 목표 비중 이탈, 집중도 신호
- 선택형 AI 코멘트

### 월간 리포트

목적: 보고서처럼 읽는 회고.

내용:

- 월간 성과와, 기존 벤치마크 데이터가 지원하는 경우 벤치마크 맥락
- 실현손익, 배당, 이자, 입출금, 현금흐름 패턴
- 자산배분 변화와 위험 신호
- 다음 달 점검 과제
- 선택형 AI 코멘트

## 데이터 흐름

기본 리포트는 로컬 데이터와 기존 서비스를 재사용해서 만든다.

1. Drift 로컬 DB에서 거래, 보유, 현금 계좌, 스냅샷, 목표 비중, 원장 기반 성과, 일별 수익률을 가져온다.
2. 기존 서비스에서 사용 가능한 시장/뉴스 맥락과 포트폴리오 진단 데이터를 가져온다.
3. 새 `ReportSnapshotBuilder`가 `오늘`, `주간`, `월간` 기간별 표준 리포트 모델을 만든다.
4. `ReportNarrativeBuilder`가 계산된 신호를 짧고 결정적인 한국어 문장으로 바꾼다.
5. AI 코치가 켜져 있으면 compact 요약 payload만 보내 보조 해석 문장을 생성한다.
6. UI는 같은 리포트 모델을 홈 요약 카드와 분석 탭 회고 허브에 렌더링한다.

## 핵심 컴포넌트

### ReportSnapshotBuilder

책임:

- 리포트 기간을 계산한다.
- 기존 로컬 DB API를 조회한다.
- 성과, 현금흐름, 자산배분, 활동, 주요 변화를 집계한다.
- UI와 AI 프롬프트 생성기가 함께 사용할 단일 리포트 스냅샷 모델을 만든다.

이 빌더는 UI에 의존하지 않아야 하며 단위 테스트가 쉬워야 한다.

### ReportNarrativeBuilder

책임:

- 계산된 리포트 신호를 결정적인 한국어 문장으로 변환한다.
- 문장은 짧고 사실 중심으로 유지한다.
- 금융 조언처럼 읽히는 표현을 피한다.
- 데이터가 부족한 경우 fallback 문장을 제공한다.

### 선택형 AI 코치

책임:

- 계산 결과를 대체하지 않고 해석만 보강한다.
- 기간, 자산군 비중, 주요 변화, 거래 수/유형, 실현 성과, 배당/이자 합계, 위험 신호 같은 compact 요약 필드만 사용한다.
- 원장 row, 계좌 식별자, 인증 식별자, 전체 거래 내역은 보내지 않는다.
- 실패하면 기본 계산 리포트를 그대로 유지하고, 필요한 경우 명시적 재시도 UI를 제공한다.

### UI 컴포넌트

책임:

- 홈 일간 회고 카드
- 분석 탭의 투자 회고 허브
- 요약, 주요 변화, 판단 피드백, 다음 액션, AI 코치 섹션 카드
- MONEYFY 기존 디자인 시스템을 재사용하는 빈 상태, 로딩, stale-data, 재시도 상태

## 오류 처리와 빈 상태

- 데이터가 부족하면 억지 해석을 만들지 않고 low-data 상태를 보여준다.
- 시장/뉴스 갱신이 실패하면 계산 리포트는 유지하고, 외부 맥락은 사용할 수 없거나 마지막 성공 데이터 기준임을 표시한다.
- AI 코치가 실패해도 결정적 리포트는 그대로 보여주며, 사용자가 AI 코치를 켠 경우에만 재시도 액션을 제공한다.
- 특정 기간에 거래가 없어도 성과, 배분, 다음 점검 프롬프트는 가능한 범위에서 보여준다.
- 스냅샷이나 벤치마크 데이터가 없으면 해당 하위 섹션을 숨기거나 정확한 unavailable 상태를 표시한다.

## 개인정보와 AI 설정

AI 코치는 기본 꺼짐이다. 사용자는 설정 또는 인라인 AI 코치 안내에서 직접 켤 수 있다.

AI 코치를 켠 경우에도 다음 원칙을 지킨다.

- compact 리포트 요약만 보낸다.
- 원장 row를 보내지 않는다.
- Supabase 사용자 ID, 이메일, 로컬 계좌 식별자, API 키를 보내지 않는다.
- AI 문장은 계산된 사실이 아니라 코치 코멘트임을 표시한다.
- AI 상태와 무관하게 로컬 결정적 리포트 섹션은 항상 유지한다.

## 테스트 전략

단위 테스트:

- 오늘/주간/월간 리포트 기간 경계
- 데이터 없음, 데이터 부족, 거래가 많은 케이스의 리포트 스냅샷 집계
- 현금흐름, 실현 성과, 배당/이자, 목표 비중 이탈 요약
- 주요 신호 조합에 대한 narrative builder 문장

위젯 테스트:

- 홈 회고 카드의 정상, low-data, stale-data, AI 실패 상태
- 분석 허브의 오늘/주간/월간 전환
- AI off/on 상태에서 결정적 리포트 섹션 유지

회귀 테스트:

- 기존 투자성과, 분석, 대시보드, 거래 흐름 테스트가 계속 통과해야 한다.
- 기존 route 호환성을 제거하지 않는다.

수동 QA:

- 모바일과 데스크톱 레이아웃을 확인한다.
- 긴 한국어 문장이 카드 안에서 겹치지 않는지 확인한다.
- 오프라인에서도 기본 리포트가 유용한지 확인한다.
- AI 코치 off 상태에서 원격 AI endpoint가 호출되지 않는지 확인한다.

## 인수 기준

- 사용자는 홈 대시보드에서 compact 일간 회고 카드를 볼 수 있다.
- 사용자는 분석 탭 또는 홈 카드에서 투자 회고 허브를 열 수 있다.
- 오늘, 주간, 월간 리포트가 모두 제공되고 같은 시각 시스템을 사용한다.
- 기본 리포트는 로그인, AI, 네트워크 연결 없이 동작한다.
- AI 코치는 원장 전체나 계정 식별 정보를 노출하지 않고 켤 수 있다.
- 빈 상태, 데이터 부족, stale-data, AI 실패 상태가 의도적으로 처리된다.
- 자동 테스트가 리포트 집계, 기간 경계, 핵심 UI 상태를 검증한다.

## 구현 메모

- 기존 투자성과, 포트폴리오 진단, 뉴스 요약, 디자인 시스템 컴포넌트를 우선 재사용한다.
- 첫 구현은 생성형 회고 리포트에 집중하고, 수동 투자 일지는 범위에서 제외한다.
- 분석 탭 밀도가 높으면 처음에는 명확한 진입 섹션으로 추가하고, 큰 route 변경은 후속 단계로 남긴다.
- 리포트 캐싱은 첫 리포트 모델이 동작한 뒤 성능상 필요가 확인되면 추가한다. 첫 버전은 로컬 데이터로 on-demand 계산하는 방향을 기본값으로 둔다.
