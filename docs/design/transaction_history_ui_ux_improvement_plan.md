# 거래 내역 화면 UI/UX 개선 계획서

## 1. 개선 목적

현재 거래 내역 화면은 다양한 기간 및 거래 유형 필터를 한 화면에 모두 노출하고 있어 화면 공간을 많이 차지하며, 거래 내역 자체에 집중하기 어렵다.

사용자가 가장 자주 수행하는 행동은 다음과 같다.

1. 특정 거래 검색
2. 거래 유형별 조회
3. 최근 기간 거래 조회
4. 상세 조건 필터링

따라서 거래 조회 효율을 높이고, 확장 가능한 구조로 개선하는 것을 목표로 한다.

## 2. 현재 구조의 문제점

### 2.1 필터 영역이 과도하게 큼

현재 구조:

```text
검색창
전체기간 1주 1개월 3개월 6개월 1년
전체유형 매수 매도 배당 이자 입금 출금 이체 환전 ...
```

문제점:

- 화면 상단 공간 과다 사용
- 거래 리스트가 아래로 밀림
- 거래 내역 확인 효율 감소

### 2.2 필터 종류가 많아 복잡함

현재 거래 유형:

- 매수
- 매도
- 배당
- 이자
- 입금
- 출금
- 이체
- 환전
- 수수료
- 세금
- 조정

총 11개 유형이 한 번에 노출된다.

문제점:

- 한 번에 인식하기 어려움
- 실제 사용 빈도가 낮은 항목도 동일하게 노출됨
- 모바일 화면에서 정보 밀도가 높음

### 2.3 필터 버튼 역할이 불명확함

현재 우측 버튼은 `≡` 형태로 보인다.

문제점:

- 메뉴인지 즉시 알기 어려움
- 정렬인지 즉시 알기 어려움
- 필터인지 즉시 알기 어려움

### 2.4 선택 상태 강조 부족

현재 선택 상태는 배경색 변화만 존재한다.

문제점:

- 현재 적용된 필터를 즉시 인식하기 어려움
- 사용자가 필터 상태를 놓치기 쉬움

## 3. 개선 방향

핵심 원칙:

1. 거래 내역 확인
2. 빠른 필터링
3. 상세 조건 검색

거래 리스트 확인을 최우선으로 두고, 자주 쓰는 조건은 빠르게 접근할 수 있게 하며, 복잡한 조건은 상세 필터로 분리한다.

## 4. 제안 UI 구조

### 4.1 상단 검색

```text

└──────────────────────┘
```

통합 검색 대상:

- 거래명

- 카테고리

### 4.2 자주 사용하는 필터만 노출

```text
[전체] [매수] [매도] [배당] [입출금]
```

특징:

- 가장 많이 사용하는 필터만 노출
- 한 줄 유지
- 빠른 접근 가능

### 4.3 상세 필터 버튼

상세 필터는 명확한 텍스트 또는 아이콘으로 제공한다.

```text

```

또는 깔때기 아이콘을 사용한다.

선택 시 BottomSheet를 연다.

## 7. 구체화 범위

### 7.1 MVP 적용 범위

이번 개선의 1차 목표는 기존 거래 조회 기능을 유지하면서 상단 필터 밀도를 낮추는 것이다.

MVP에 포함한다:

- 검색창 유지 및 시각적 밀도 축소
- 빠른 거래 유형 필터 5개 노출
- 기존 기간 필터를 상세 필터 BottomSheet로 이동
- 전체 거래 유형 필터를 상세 필터 BottomSheet로 이동
- 정렬 옵션을 상세 필터 BottomSheet로 이동
- 필터 적용 상태를 버튼 배지와 요약 텍스트로 표시
- 조건 초기화 동작 유지

MVP에서 제외한다:

- DB schema 변경
- 원장 계산 로직 변경
- 서버 sync 변경
- 거래 CRUD 동작 변경
- 거래소, 태그, 사용자 정의 카테고리 실제 데이터 모델 추가
- 캘린더 보기, 통계 보기 등 별도 뷰 모드 추가

### 7.2 현재 코드 기준

현재 `lib/pages/transactions_page.dart`에는 다음 구조가 이미 존재한다.

- `_TransactionQueryPanel`: 검색창, 정렬 버튼, 기간 필터, 거래 유형 필터를 렌더링한다.
- `_TransactionPeriodFilter`: 전체 기간, 1주, 1개월, 3개월, 6개월, 1년 필터를 정의한다.
- `_TransactionCategoryFilter`: 전체 유형과 11개 거래 유형 필터를 정의한다.
- `_TransactionSortMode`: 최신순, 오래된순, 금액 큰순, 금액 작은순을 정의한다.
- `_FilterStrip`: 가로 스크롤 칩 목록을 렌더링한다.

따라서 1차 구현은 새 데이터 모델을 만드는 작업이 아니라, 기존 enum과 필터 로직을 재배치하고 UI 컴포넌트를 분리하는 작업으로 진행한다.

## 8. 상세 UX 명세

### 8.1 상단 검색 영역

검색창은 거래 리스트를 직접 필터링하는 1차 행동으로 유지한다.

권장 사양:

- placeholder: `거래 검색`
- 검색 대상: 거래명, 종목명, 계좌명, 거래 유형, 메모성 이름 필드
- 검색어 입력 즉시 리스트 갱신
- 입력값이 있을 때 우측에 지우기 버튼 표시
- 검색어가 적용된 상태에서는 필터 요약에 `검색어: {입력값}`을 포함

시각 사양:

- 현재처럼 pill 형태는 유지하되 검색창과 필터 영역을 카드 안에 과하게 묶지 않는다.
- 상단 영역은 `검색창 + 빠른 필터 행` 2단 구성을 기본으로 한다.
- 검색창 우측에는 정렬 아이콘 대신 명확한 `필터` 버튼을 둔다.

### 8.2 빠른 필터 칩

빠른 필터는 가장 자주 쓰는 유형만 노출한다.

| 칩 | 매칭 거래 |
| --- | --- |
| 전체 | 모든 거래 |
| 매수 | `buy`, `매수` |
| 매도 | `sell`, `매도` |
| 배당 | `dividend`, `배당` |
| 입출금 | `deposit`, `withdrawal`, `opening_cash`, `입금`, `출금` |

동작 사양:

- 빠른 필터는 단일 선택이다.
- 기본값은 `전체`이다.
- 빠른 필터 선택 시 상세 필터의 거래 유형 선택과 동기화한다.
- 사용자가 상세 필터에서 빠른 필터로 표현할 수 없는 조합을 선택하면 빠른 필터는 `전체`로 보이고, 필터 버튼 배지와 요약 텍스트로 상세 조건을 표시한다.

선택 상태 사양:

- 선택된 칩은 배경색, 텍스트 굵기, 체크 아이콘 중 최소 2가지 이상으로 강조한다.
- 비선택 칩은 외곽선과 중립 텍스트 색을 사용한다.
- 칩 높이는 고정해 선택 상태 변경 시 레이아웃이 흔들리지 않게 한다.

### 8.3 상세 필터 버튼

기존 정렬 아이콘 단독 버튼은 사용자가 역할을 즉시 알기 어렵다. 버튼은 다음 중 하나로 변경한다.

권장안:

```text
[깔때기 아이콘] 필터
```

보조 사양:

- 적용된 상세 필터가 있으면 버튼 우측 상단에 작은 배지를 표시한다.
- 배지 숫자는 적용된 조건 그룹 수를 표시한다.
- 상세 필터가 하나라도 적용된 경우 버튼 색을 primary 계열로 강조한다.
- 접근성 label은 `거래 상세 필터`로 지정한다.

### 8.4 적용 필터 요약

필터가 기본값이 아닐 때만 검색/칩 하단에 요약 행을 표시한다.

예시:

```text
최근 1개월 · 매수, 배당 · 금액 높은순
```

요약 행 사양:

- 기본 상태에서는 숨긴다.
- 검색어, 기간, 상세 거래 유형, 계좌, 자산, 정렬이 기본값이 아닐 때 표시한다.
- 우측에는 `초기화` 텍스트 버튼을 둔다.
- 한 줄을 넘으면 말줄임 처리한다.

## 9. 상세 필터 BottomSheet 명세

### 9.1 구조

BottomSheet는 다음 순서로 구성한다.

```text
상단 핸들
제목: 상세 필터
초기화 버튼

기간
거래 유형
계좌
자산
정렬

하단 고정 영역
[초기화] [결과 보기]
```

레이아웃 사양:

- 모바일 기본 높이: 화면 높이의 70~85%
- `isScrollControlled: true` 사용
- 내부 콘텐츠만 스크롤
- 하단 액션 영역은 고정
- 키보드가 열릴 수 있는 검색형 필터가 추가될 경우 `viewInsets.bottom` 반영

### 9.2 기간 필터

기간은 단일 선택이다.

| 옵션 | 동작 |
| --- | --- |
| 전체 | 기간 제한 없음 |
| 1주 | 오늘 포함 최근 7일 |
| 1개월 | 오늘 포함 최근 31일 |
| 3개월 | 오늘 포함 최근 93일 |
| 6개월 | 오늘 포함 최근 186일 |
| 1년 | 오늘 포함 최근 366일 |
| 사용자 지정 | 시작일/종료일 직접 선택 |

MVP에서는 기존 enum 범위인 `전체~1년`을 우선 지원하고, 사용자 지정은 2차 범위로 둔다.

### 9.3 거래 유형 필터

거래 유형은 다중 선택으로 설계한다.

MVP 구현 방식:

- 기존 `_TransactionCategoryFilter`는 단일 선택 구조이므로 1차 구현에서는 단일 선택을 유지할 수 있다.
- 다중 선택 전환은 후속 단계에서 `Set<_TransactionCategoryFilter>`로 상태를 변경한다.

최종 목표:

- `전체` 선택 시 개별 선택을 모두 해제한다.
- 개별 유형을 하나 이상 선택하면 `전체`는 해제한다.
- 아무 유형도 선택하지 않으면 `전체`와 동일하게 처리한다.

### 9.4 계좌 필터

계좌 필터는 `data.accounts`에서 동적으로 구성한다.

MVP:

- BottomSheet에 섹션 자리와 정책을 명시한다.
- 실제 필터 적용은 2차 구현으로 둔다.

2차 구현:

- 전체 계좌
- 투자 계좌/보유 종목 계좌
- 현금 계좌
- 계좌명 검색

### 9.5 자산 필터

자산 필터는 거래량이 많아진 뒤 효과가 커지는 조건이다.

MVP:

- 문서와 UI 확장 슬롯만 정의한다.
- 실제 적용은 2차 구현으로 둔다.

2차 구현:

- 전체
- 보유 자산명
- 티커/심볼
- 현금성 자산 제외 토글

### 9.6 정렬

정렬은 단일 선택이다.

| 옵션 | 기존 enum |
| --- | --- |
| 최신순 | `_TransactionSortMode.dateDesc` |
| 오래된순 | `_TransactionSortMode.dateAsc` |
| 금액 높은순 | `_TransactionSortMode.amountDesc` |
| 금액 낮은순 | `_TransactionSortMode.amountAsc` |

기존 PopupMenuButton은 제거하고 BottomSheet 내부 섹션으로 이동한다.

## 10. 구현 계획

### 10.1 1단계: UI 구조 재배치

대상 파일:

- `lib/pages/transactions_page.dart`

작업:

- `_TransactionQueryPanel`에서 기간 필터 strip 제거
- `_TransactionQueryPanel`에서 전체 거래 유형 strip 제거
- 검색창 우측 정렬 버튼을 상세 필터 버튼으로 교체
- 빠른 필터 전용 enum 또는 매핑 추가
- 빠른 필터 칩 strip 추가
- 필터 요약 행 추가

검증:

- 기본 화면에서 검색창, 빠른 필터 5개, 필터 버튼만 노출된다.
- 거래 리스트 시작 위치가 기존보다 위로 올라온다.
- 검색어 입력과 조건 초기화가 기존처럼 동작한다.

### 10.2 2단계: BottomSheet 추가

대상 파일:

- `lib/pages/transactions_page.dart`

작업:

- `_TransactionFilterSheet` 위젯 추가
- 기간, 거래 유형, 정렬 섹션 추가
- BottomSheet 내부 임시 상태를 사용해 취소/적용 흐름 분리
- `결과 보기`를 누를 때만 부모 상태에 반영
- `초기화` 버튼으로 검색어를 제외한 필터 조건 초기화

검증:

- 필터 버튼을 누르면 BottomSheet가 열린다.
- 선택 후 닫지 않고 뒤로 가기/바깥 터치 시 기존 조건이 유지된다.
- `결과 보기`를 누르면 리스트가 갱신된다.
- `초기화`를 누르면 기간/유형/정렬이 기본값으로 돌아간다.

### 10.3 3단계: 선택 상태와 적용 상태 강화

작업:

- 선택된 빠른 필터 칩에 체크 아이콘 또는 명확한 selected 스타일 적용
- 상세 필터 적용 시 필터 버튼 배지 표시
- 요약 행에 적용 조건 표시
- 빈 결과 카드의 `조건 초기화` 동작 유지

검증:

- 사용자가 현재 적용된 조건을 상단에서 즉시 확인할 수 있다.
- 상세 필터가 적용된 상태와 기본 상태가 시각적으로 구분된다.

### 10.4 4단계: 테스트 보강

대상 파일:

- `test/page_walkthrough_test.dart`
- 필요 시 `test/ui_component_smoke_test.dart`

테스트 항목:

- 거래 페이지 smoke 테스트에서 빠른 필터와 필터 버튼 렌더링 확인
- 빠른 필터 선택 시 거래 리스트가 필터링되는지 확인
- 상세 필터 BottomSheet 오픈 확인
- 정렬 선택 후 결과 순서 변경 확인
- 조건 초기화 버튼 동작 확인

### 10.5 5단계: 2차 확장 후보

MVP 이후 다음 항목을 별도 작업으로 분리한다.

- 거래 유형 다중 선택
- 사용자 지정 기간
- 계좌 필터 실제 적용
- 자산 필터 실제 적용
- 필터 조건 저장 또는 최근 필터 기억
- 태블릿/데스크톱 사이드 패널 전환

## 11. 수용 기준

기능 기준:

- 검색어 입력 시 거래명, 종목명, 계좌명, 거래 유형 기준으로 거래가 필터링된다.
- 빠른 필터는 전체, 매수, 매도, 배당, 입출금을 단일 선택으로 제공한다.
- 상세 필터에서 기간과 정렬을 변경할 수 있다.
- 상세 필터 적용 후 상단에서 적용 상태를 확인할 수 있다.
- 조건 초기화 시 검색어, 기간, 유형, 정렬이 기본값으로 돌아간다.

UI 기준:

- 기본 거래 화면에서 필터 칩은 한 줄로 유지된다.
- 기존처럼 2줄 이상의 필터 strip이 상단을 차지하지 않는다.
- 필터 버튼은 역할이 명확해야 한다.
- 선택 상태는 배경색만으로 의존하지 않는다.
- 빈 결과 상태에서 사용자가 바로 조건을 초기화할 수 있다.

회귀 방지 기준:

- 거래 추가, 수정, 삭제 흐름은 변경되지 않는다.
- pull-to-refresh 동작은 유지된다.
- 원장 이벤트 그룹핑은 유지된다.
- 기존 정렬 결과와 동일한 기준을 사용한다.
- `flutter analyze` 통과
- 관련 widget test 통과

## 12. 기대 효과

### 12.1 사용성 향상

- 거래 내역 노출 영역 증가
- 스크롤 감소
- 빠른 거래 탐색 가능

### 12.2 확장성 확보

향후 추가 가능한 조건:

- 계좌
- 자산
- 거래소
- 태그
- 사용자 정의 카테고리

조건이 추가되어도 상세 필터 BottomSheet로 흡수할 수 있어 기본 화면의 복잡도 증가를 최소화할 수 있다.

### 12.3 금융 앱 표준 패턴 적용

최근 금융 서비스들은 대부분 다음 구조를 사용한다.

```text
검색
↓
핵심 필터 칩
↓
상세 필터 BottomSheet
↓
거래 리스트
```

MONEYFY 역시 해당 구조를 적용하면 거래 수가 수천 건 이상으로 증가하더라도 일관된 사용자 경험을 유지할 수 있다.

## 13. 참고 레퍼런스

### 13.1 Apple Human Interface Guidelines: Search Fields

- URL: https://developer.apple.com/design/human-interface-guidelines/search-fields
- 참고 포인트:
  - 검색이 특정 화면의 콘텐츠를 대상으로 할 때는 콘텐츠와 가까운 위치에 검색 필드를 배치하는 것이 적절하다.
  - 거래 내역 화면의 상단 검색창은 전역 검색이 아니라 거래 리스트를 필터링하는 맥락 검색으로 설계하는 것이 자연스럽다.
  - iOS 환경에서는 검색 진입점의 위치가 화면 구조와 주요 작업에 따라 달라질 수 있으므로, 거래 리스트 확인을 방해하지 않는 배치가 중요하다.

### 13.2 Material Design: Chips

- URL: https://m2.material.io/components/chips
- 참고 포인트:
  - 필터 칩은 여러 조건 중 일부를 빠르게 선택하거나 해제하는 데 적합하다.
  - MONEYFY의 상단 빠른 필터는 `전체`, `매수`, `매도`, `배당`, `입출금`처럼 사용 빈도가 높은 조건만 칩으로 노출한다.
  - 선택된 칩은 배경색만 바꾸기보다 텍스트 굵기, 체크 아이콘, 대비 높은 색상 등으로 상태를 명확히 표현하는 것이 좋다.

### 13.3 Material Design: Bottom Sheets

- URL: https://m2.material.io/components/sheets-bottom
- 참고 포인트:
  - BottomSheet는 모바일 화면에서 보조 작업이나 상세 옵션을 현재 맥락 위에 제공하는 데 적합하다.
  - 기간, 계좌, 자산, 정렬처럼 항목 수가 많거나 자주 쓰이지 않는 조건은 기본 화면에서 분리해 BottomSheet에 배치한다.
  - 큰 화면에서는 BottomSheet를 그대로 넓게 펼치기보다 최대 너비 제한, 플로팅 시트, 사이드 시트 전환을 고려할 수 있다.

### 13.4 Wellspent: Transaction List Reference

- URL: https://trywellspent.com/
- 참고 포인트:
  - 실제 개인금융 앱 사례로, 거래 목록에서 계좌 필터, 이름 검색, 날짜 탐색을 핵심 조회 방식으로 제시한다.
  - “거래를 한 곳에서 보고, 필요한 조건으로 좁힌다”는 구조가 MONEYFY의 개선 방향과 유사하다.
  - 거래 내역 화면은 많은 기능을 한 번에 보여 주기보다 자주 쓰는 조회 행동을 우선 배치하는 것이 좋다.

### 13.5 MoneySpent: Searchable Spend History

- URL: https://www.moneyspent.app/
- 참고 포인트:
  - 거래 히스토리에서 검색, 날짜, 계좌, 유형 필터를 함께 제공하는 개인금융 앱 사례다.
  - 리스트와 캘린더형 보기 전환을 언급하고 있어, 향후 MONEYFY에서도 거래 수가 많아질 경우 보기 모드 확장의 참고가 될 수 있다.
  - 빠른 입력, 빠른 조회, 간결한 거래 리스트를 함께 강조한다는 점에서 거래 화면의 정보 밀도 조절에 참고할 만하다.

### 13.6 적용 시사점

- 검색은 거래 리스트와 직접 연결된 1차 행동으로 유지한다.
- 빠른 필터 칩은 4~5개 수준으로 제한해 한 줄을 유지한다.
- 상세 조건은 BottomSheet로 이동해 기본 화면의 리스트 노출 영역을 확보한다.
- 선택된 필터는 칩 상태, 필터 버튼 배지, 적용 조건 요약 등으로 명확히 드러낸다.
- 모바일 우선 구조를 유지하되 태블릿/데스크톱에서는 BottomSheet 대신 사이드 패널 전환 가능성을 열어 둔다.
