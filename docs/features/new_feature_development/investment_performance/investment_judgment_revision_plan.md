# Investment Performance Judgment Revision Plan

작성일: 2026-05-30

## Goal

`투자성과 분석` 페이지를 현재의 원장 집계 리포트에서 사용자가 투자 판단을 바로 할 수 있는 성과 리포트로 수정한다.

현재 페이지는 표시 정보가 충분하지만, 사용자가 다음 질문에 답하기에는 위계와 해석이 약하다.

1. 이 기간 내 투자는 실제로 잘됐는가?
2. 금액 성과와 수익률 성과 중 무엇을 기준으로 판단해야 하는가?
3. 시장과 비교했을 때 의미 있는 성과인가?
4. 성과는 투자 실력, 현금흐름, 평가손익, 비용 중 어디에서 왔는가?
5. 어떤 종목이나 월이 판단을 바꾸는 핵심 원인인가?

이 수정 계획은 `무엇을 보여주는가`보다 `어떤 판단을 돕는가`를 우선한다.

## Product Diagnosis

현재 구조의 핵심 문제는 정보 부족이 아니라 판단 축 부족이다.

| 문제 | 현재 상태 | 사용자 영향 |
| --- | --- | --- |
| 대표 지표 혼선 | `순 투자성과` 금액이 최상단 대표 지표 | 자산 규모가 큰 사용자의 성과가 항상 좋아 보일 수 있음 |
| 수익률 정의 혼재 | 매수 원금 대비 수익률과 입출금 보정 기간 수익률이 분리 설명 없이 공존 | 서로 다른 수익률을 같은 성격으로 오해할 수 있음 |
| 벤치마크 단일화 | 모든 사용자에게 `S&P 500`을 시장 비교처럼 표시 | 국내/혼합/현금성 포트폴리오에서는 비교가 왜곡될 수 있음 |
| 종목별 비용 미배분 | 종목별 총 성과는 비용 차감 전 성격 | 종목별 기여도가 실제 순성과보다 좋게 보일 수 있음 |
| 월별 성과 범위 제한 | 월별 섹션은 실현성과 중심 | 해당 월 계좌 성과 전체로 오해될 수 있음 |
| 총자산 변화와 미연결 | 제외 현금흐름을 따로 표시하지만 총자산 변화와 검산하지 않음 | 사용자가 숫자가 맞는지 확인하기 어려움 |
| 고급 지표 해석 부족 | Sharpe, 변동성, 최대 낙폭을 숫자로 표시 | 일반 사용자에게 행동 가능한 의미가 약함 |

## Target Experience

수정 후 첫 화면은 다음 판단 흐름을 만든다.

```text
1. 이번 기간 수익률은 어땠나?
2. 실제 돈으로는 얼마 벌거나 잃었나?
3. 이 성과는 시장/벤치마크 대비 어떤가?
4. 성과를 만든 가장 큰 원인은 무엇인가?
5. 총자산 변화와 투자성과 숫자가 어떻게 이어지는가?
```

## Revision Principles

### 1. Rate Leads Judgment, Amount Explains Impact

성과 판단의 대표 지표는 `입출금 보정 기간 수익률`로 둔다. `순 투자성과` 금액은 사용자가 체감하는 금액 영향으로 함께 보여준다.

| 지표 | 역할 | 표시 위계 |
| --- | --- | --- |
| 입출금 보정 기간 수익률 | 투자 판단의 대표 지표 | 최상단 main |
| 순 투자성과 | 실제 금액 영향 | 최상단 secondary |
| 매수 원금 대비 수익률 | 원장 기반 보조 비율 | tooltip/helper 또는 보조 배지 |
| 초과수익률 | 벤치마크 대비 판단 | benchmark 영역 |

### 2. Benchmark Is A Reference, Not The Market

`S&P 500`은 기본 참고 벤치마크일 뿐, 모든 포트폴리오의 시장 대표값으로 표현하지 않는다.

문구를 다음처럼 바꾼다.

| 현재 의미 | 수정 방향 |
| --- | --- |
| `시장 비교와 위험` | `벤치마크와 위험` 또는 `참고 지표` |
| `시장 대비` | `S&P 500 대비` |
| `S&P 500보다 +2.1%p` | `참고 벤치마크 S&P 500 대비 +2.1%p` |

장기적으로는 사용자 선택형 벤치마크를 추가한다.

| 단계 | 벤치마크 |
| --- | --- |
| v1 | S&P 500 기본값 유지, 표현만 참고 벤치마크로 수정 |
| v2 | KOSPI, NASDAQ, S&P 500 프리셋 |
| v3 | 포트폴리오 통화/자산구성 기반 추천 벤치마크 |
| v4 | 사용자 지정 벤치마크 |

### 3. Reconcile Before Explaining Details

투자성과와 현금흐름을 따로 보여주는 데서 끝내지 않고, 총자산 변화와 연결한다.

추가할 카드:

```text
총자산 변화 검산

시작 총자산       10,000,000원
순 투자성과        +420,000원
외부 입출금        +300,000원
기타/내부 이동          0원
종료 총자산       10,720,000원
차이                    0원
```

초기 구현에서 시작/종료 총자산을 안정적으로 구할 수 없으면 `성과와 현금흐름 연결` 카드로 축소한다.

```text
순 투자성과 + 외부 입출금 = 기간 중 계좌 변화의 핵심 원인
```

단, 내부 이동과 결제 현금흐름은 총자산 변화에는 중복 계산될 수 있으므로 검산식에는 별도 주석을 둔다.

### 4. State Scope Clearly

실현, 미실현, 비용, 현금흐름의 범위를 화면 안에서 명확히 분리한다.

| 영역 | 반드시 밝혀야 할 한계 |
| --- | --- |
| 월별 실현성과 | 월별 그래프는 실현손익/수입/비용 중심이며 미실현 평가 변화는 포함하지 않음 |
| 종목별 성과 | 수수료/세금은 전체 비용으로 표시하며 종목별 비용 배분은 v1에서 하지 않음 |
| 매수 원금 대비 수익률 | 입출금 보정 기간 수익률과 다른 단순 원금 대비 비율 |
| 미실현손익 | 시작 전 스냅샷이 없으면 현재 미실현손익 전체가 반영될 수 있음 |

### 5. Translate Risk Metrics Into Meaning

고급 지표는 숫자만 표시하지 않고 짧은 해석 문장과 함께 보여준다.

| 지표 | 해석 예시 |
| --- | --- |
| 기간 수익률 | `입출금 영향을 제외하면 선택 기간 수익률은 +4.2%입니다.` |
| 초과수익률 | `S&P 500보다 1.8%p 높았습니다.` |
| 변동성 | `수익률 변동이 큰 편입니다.` |
| Sharpe | `위험 대비 성과가 충분한지 판단하려면 더 긴 기간 데이터가 필요합니다.` |
| 최대 낙폭 | `선택 기간 중 고점 대비 최대 -7.4%까지 하락했습니다.` |

## Proposed Page IA

### 1. Performance Judgment Header

기존 `순 투자성과` 중심 cockpit을 `기간 수익률` 중심으로 재구성한다.

표시 정보:

| 위계 | 표시 정보 |
| --- | --- |
| Primary | 입출금 보정 기간 수익률 |
| Secondary | 순 투자성과 금액 |
| Supporting | 매수 원금 대비 수익률, 순 실현성과, 미실현손익 |
| Context | 선택 기간, 데이터 부족 상태, 계산 기준 |

예시:

```text
기간 수익률
+4.2%
입출금 영향을 제외한 성과

순 투자성과 +420,000원
매수 원금 대비 +3.8%
```

데이터 부족 시:

```text
기간 수익률 데이터 부족
순 투자성과 +420,000원
스냅샷/일별 평가 데이터가 쌓이면 수익률을 표시합니다.
```

### 2. Benchmark Snapshot

기존 `시장 비교와 위험`에서 벤치마크 비교를 분리해 상단 가까이에 둔다.

표시 정보:

| 표시명 | 내용 |
| --- | --- |
| 내 기간 수익률 | 입출금 보정 기간 수익률 |
| 참고 벤치마크 | 기본 `S&P 500` |
| 초과수익률 | 내 기간 수익률 - 벤치마크 수익률 |
| 데이터 상태 | 가격 부족, 기간 부족, 네트워크 실패 안내 |

표현 원칙:

- `시장`이라는 단어는 기본값에서는 피한다.
- `S&P 500`은 참고 기준으로 표시한다.
- 국내/혼합 포트폴리오 사용자에게 과도한 평가처럼 들리지 않게 한다.

### 3. Performance Attribution

기존 성과 원인 카드는 유지하되, 판단 문장을 추가한다.

추가 정보:

| 항목 | 목적 |
| --- | --- |
| 가장 큰 플러스 요인 | 성과를 만든 주된 원인 |
| 가장 큰 마이너스 요인 | 성과를 깎은 주된 원인 |
| 비용 영향 | 수수료/세금이 순성과를 얼마나 줄였는지 |

예시:

```text
이번 기간 성과는 미실현손익이 가장 크게 만들었습니다.
수수료와 세금은 총 32,000원으로 성과를 낮췄습니다.
```

### 4. Asset Change Reconciliation

신규 섹션이다.

목표:

- `투자성과`, `외부 입출금`, `총자산 변화`를 연결한다.
- 사용자가 "계좌는 왜 늘었는데 성과는 적지?"를 이해하게 한다.

표시 정보:

| 표시명 | 설명 |
| --- | --- |
| 순 투자성과 | 투자 활동으로 발생한 성과 |
| 외부 입출금 | 사용자가 넣거나 뺀 돈 |
| 내부 이동 | 계좌 간 이동/환전 규모 |
| 투자 결제 현금흐름 | 매수/매도 결제 현금흐름 |
| 총자산 변화 연결 상태 | 스냅샷이 있으면 시작/종료 총자산 기준 검산 |

v1에서는 정확한 총자산 변화 검산에 필요한 데이터가 부족하면 기존 `제외 현금흐름` 카드를 이 섹션으로 이름과 설명만 바꾼다.

### 5. Monthly Trend

기존 월별 실현성과를 유지하되 이름과 범위를 더 명확히 한다.

수정안:

| 현재 | 수정 |
| --- | --- |
| `월별 실현성과` | `월별 확정 성과` |
| 설명 없음 | `미실현 평가 변화는 포함하지 않습니다.` |

장기 개선:

| 단계 | 추가 내용 |
| --- | --- |
| v1 | 월별 확정 성과 명확화 |
| v2 | 월초/월말 스냅샷 기반 월별 미실현 변화 |
| v3 | 월별 총 투자성과 = 확정 성과 + 평가손익 변화 |

### 6. Holding Contribution

종목별 성과는 그대로 두되, 비용 배분 한계를 명확히 표시한다.

v1 수정:

- `종목별 성과` 하단 또는 header caption에 `수수료/세금은 전체 비용으로 표시되며 종목별로 배분하지 않습니다.`를 추가한다.
- 총 성과 옆에 `비용 전` 또는 `비용 미배분` 뉘앙스를 반영한다.
- 기여율의 기준이 `전체 순 투자성과`임을 tooltip/helper에 명시한다.

v2 후보:

| 비용 배분 방식 | 장점 | 단점 |
| --- | --- | --- |
| 거래 라인 holding_id 기준 직접 배분 | 가장 정확 | 일부 비용 라인의 holding_id 누락 가능 |
| 매수/매도 금액 비례 배분 | 전체 일관성 | 실제 비용 귀속과 다를 수 있음 |
| 배분하지 않음 | 단순하고 안전 | 종목별 순성과 판단이 제한됨 |

권장: v1은 배분하지 않고 명시한다. v2에서 holding_id가 있는 fee/tax만 종목별 보조 비용으로 표시한다.

### 7. Risk Interpretation

위험 지표는 별도 숫자 그리드로만 두지 않고 해석을 붙인다.

수정안:

| 지표 | 표시 방식 |
| --- | --- |
| 변동성 | 숫자 + `변동이 큰/작은 편` |
| Sharpe | 숫자 + 관측치 부족 시 명확한 안내 |
| 최대 낙폭 | 숫자 + 선택 기간 중 가장 큰 하락폭 문장 |

데이터 부족 사유도 구분한다.

| 상태 | 사용자 문구 |
| --- | --- |
| 일별 수익률 부족 | `평가 데이터가 더 쌓이면 표시됩니다.` |
| 벤치마크 가격 부족 | `참고 벤치마크 가격을 아직 확보하지 못했습니다.` |
| 금리 부족 | `무위험수익률은 임시로 0% 기준을 사용했습니다.` |
| 관측치 부족 | `Sharpe는 최소 기간 데이터가 더 필요합니다.` |

## Implementation Plan

### Phase 1. Copy And IA Correction

목표: 계산 로직을 크게 바꾸지 않고 오해를 줄인다.

작업:

1. `시장 비교와 위험`을 `벤치마크와 위험` 계열 문구로 변경한다.
2. `시장 대비`를 `S&P 500 대비`로 변경한다.
3. 월별 섹션에 미실현손익 미포함 안내를 추가한다.
4. 종목별 섹션에 비용 미배분 안내를 추가한다.
5. 매수 원금 대비 수익률과 입출금 보정 기간 수익률의 차이를 helper 문구로 분리한다.

검증:

- `flutter analyze lib/pages/investment_performance_page.dart`
- 투자성과 페이지 widget smoke
- 390dp 화면에서 문구 overflow 확인

### Phase 2. Header Metric Reorder

목표: 금액 중심 cockpit을 수익률 판단 중심으로 바꾼다.

작업:

1. `_PerformanceCockpitCard`의 primary metric을 `advancedPerformance.periodReturn`으로 변경한다.
2. `순 투자성과`는 secondary amount로 유지한다.
3. 기간 수익률 데이터가 없을 때는 기존 순 투자성과를 primary fallback으로 표시한다.
4. 매수 원금 대비 수익률은 `원금 대비` 보조 배지로 낮춘다.

검증:

- 기간 수익률 있음/없음 fixture 테스트
- 매수 원금 0일 때 비율 미표시 테스트
- 데이터 없는 첫 사용자 화면 확인

### Phase 3. Interpretation Layer

목표: 숫자에서 판단 문장으로 이동한다.

작업:

1. 성과 원인 카드에 가장 큰 플러스/마이너스 요인 문장 추가.
2. 벤치마크 비교 문장을 `참고 벤치마크` 기준으로 재작성.
3. 위험 지표에 데이터 부족 사유와 짧은 해석 문장 추가.
4. 양수/음수/데이터 부족 상태별 문구 테이블을 테스트로 고정.

검증:

- copy snapshot/widget expectation
- 긴 한글 문구 360/390/430dp overflow 확인

### Phase 4. Asset Change Reconciliation

목표: 총자산 변화, 투자성과, 현금흐름을 연결한다.

작업:

1. 선택 기간의 시작/종료 포트폴리오 스냅샷 확보 가능 여부 확인.
2. 가능하면 시작 총자산, 종료 총자산, 순 투자성과, 외부 입출금, 잔차를 표시한다.
3. 불가능하면 기존 제외 현금흐름 카드를 `성과에서 제외한 현금흐름` + 설명형 카드로 개선한다.
4. 내부 이동과 결제 현금흐름은 총자산 검산과 직접 합산하지 않는다는 주석을 둔다.

검증:

- 스냅샷 있음/없음 케이스
- 외부 입금만 있는 기간
- 매수/매도 결제만 있는 기간
- 내부 이동/환전이 있는 기간

### Phase 5. Better Monthly And Holding Attribution

목표: 월별/종목별 상세가 대표 지표와 더 잘 맞게 한다.

작업:

1. 월별 미실현 변화 계산 가능성을 검토한다.
2. 월별 `확정 성과`와 `평가 변화`를 분리 표시한다.
3. 종목별 비용 배분 정책을 결정한다.
4. holding_id가 있는 fee/tax만 종목별 보조 비용으로 표시하는 v2안을 검토한다.

검증:

- 월별 총성과와 전체 기간 성과의 reconciliation 테스트
- fee/tax holding_id 유무에 따른 비용 배분 테스트

| 항목 | 계획 |
| --- | --- |
| S&P 500 단일 벤치마크 | v1에서는 참고 표현으로 완화, v2에서 선택형 검토 |

| 환율 기준 차이 | 전체/월별 집계와 종목별 환산 기준을 문서와 helper에 명시 |

## Acceptance Criteria

1. 첫 화면에서 `기간 수익률`, `순 투자성과`, `참고 벤치마크 대비`를 구분해서 이해할 수 있다.
2. 사용자가 `매수 원금 대비 수익률`과 `입출금 보정 기간 수익률`을 같은 지표로 오해하지 않는다.
3. S&P 500 비교가 모든 포트폴리오의 절대 시장 평가처럼 보이지 않는다.
4. 종목별 성과에 비용이 배분되지 않았다는 점이 화면 또는 helper에서 확인된다.
5. 월별 그래프가 미실현 평가 변화를 포함하지 않는다는 점이 명확하다.
6. 데이터 부족 상태가 단순 `데이터 부족`보다 구체적인 이유로 표시된다.
7. 현금흐름 제외 카드가 총자산 변화 또는 성과 해석과 연결된다.

## Out Of Scope

다음은 이 수정 계획의 v1 범위에서 제외한다.

- 사용자 지정 벤치마크 생성
- IRR/MWRR/XIRR 신규 계산
- 종목별 비용 완전 배분
- 월별 총 투자성과 완전 reconciliation
- 거래 drill-down 신규 상세 화면
- 세금 최적화 또는 투자 조언 문구
