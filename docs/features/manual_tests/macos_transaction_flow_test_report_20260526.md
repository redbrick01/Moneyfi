## 요약

매수, 매도, 입금, 출금, 이체, 환전의 상태 반영은 기대값과 일치했다.

다만 현재 실행 중인 Release 앱에서 새 투자 거래 폼과 새 현금 거래 폼 모두 `포트폴리오 계산에 반영` 스위치가 기본 off로 표시되는 문제가 재현됐다. 이 상태로 저장하면 기록전용 거래가 되므로, 테스트 중에는 각 거래 저장 전 스위치를 수동으로 켠 뒤 진행했다.

## 기준 상태

앱 화면에서 확인:

- `테스트 주식 현금`: `1,020,000원`

- 거래 내역에는 seed 이후 추가된 `manual buy`, `manual sell` 정산 라인이 표시되어 있었다.

이전 테스트 진행 중 매수/매도 케이스가 먼저 실행되어 기준 현금은 `1,020,000원`이었다.

## 발견 이슈

### P1. 현재 실행 중인 Release 앱의 계산 반영 기본값이 off

재현 위치:

- 투자 거래 추가 폼
- 현금 거래 추가 폼

재현 내용:

- 새 거래 추가 화면 진입 시 `포트폴리오 계산에 반영` 스위치가 off로 표시된다.
- off 상태에서 저장하면 현재 보유 수량, 평단, 현금 잔액에 반영되지 않는 기록전용 거래가 된다.

영향:

- 사용자가 일반 매수/매도/현금 거래를 입력해도 기본 상태 그대로 저장하면 포트폴리오 계산에 반영되지 않는다.

비고:

- 코드상으로는 `lib/pages/forms/transaction_form_page.dart`와 `lib/pages/forms/cash_transaction_form_page.dart`에서 새 거래 기본값을 true로 수정해 둔 상태다.
- 이번 수동 테스트 대상은 이미 실행 중이던 Release 앱이므로 해당 수정이 반영되지 않은 빌드로 보인다.

## 실행 중 특이사항

- Korean IME 입력은 Computer Use `type_text`에서 제대로 입력되지 않아 테스트 거래명은 `manual buy`, `manual sell`처럼 ASCII로 입력했다.
- 거래 저장 시 `저장 중...` 상태가 몇 초 지속되었으나 모든 케이스에서 최종 저장 및 화면 복귀가 완료됐다.
- Supabase CLI는 실행 때마다 Bun AVX 경고와 CLI 업데이트 안내를 출력했으나 쿼리 실행에는 영향이 없었다.

## 결론

거래 유형별 핵심 계산 로직은 정상 동작한다. 현재 확인된 주요 UX/기능 위험은 새 거래 폼의 계산 반영 기본값이 실행 중인 앱에서 off인 점이다. 수정된 코드를 포함해 Release 앱을 다시 빌드한 뒤, 새 거래 폼 진입 시 스위치 기본값이 on인지 재확인해야 한다.
